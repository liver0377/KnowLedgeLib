## 二、核心组件

### 1. Checkpointer（检查点）- 对话级记忆

**作用**：保存和恢复对话状态（State）

**自动机制**：
```python
# 在 lifespan 中设置一次
agent.checkpointer = saver

# 之后完全自动化
await agent.ainvoke(
    input=...,
    config={"configurable": {"thread_id": "abc-123"}}  # 自动根据 thread_id 读写
)
```

**数据结构**：
```sql
CREATE TABLE checks (
    thread_id TEXT,
    checkpoint_ns TEXT,
    checkpoint_id TEXT,
    parent_checkpoint_id TEXT,
    type TEXT,
    checkpoint JSONB,        -- 完整的 State（包括 messages）
    metadata JSONB
);
```

**存储内容**：完整的 `AgentState`，包括：
- `messages`: 所有对话消息历史
- 其他状态字段（如 `retrieved_documents`, `generated_sql` 等）

**隔离级别**：`thread_id` 级别
- 每个 `thread_id` 有独立的对话历史
- 相同 `user_id` 的不同 `thread_id` 互不干扰

---

### 2. Store（长期存储）- 用户级记忆

**作用**：跨对话保存键值对数据

**手动机制**：
```python
async def my_node(state, config, store):
    # 手动读取
    result = await store.aget((user_id,), "key")

    # 手动写入
    await store.aput((user_id,), "key", {"data": ...})
```

**数据结构**：
```sql
CREATE TABLE store (
    namespace TEXT[],      -- 例如 ["user_123"]
    key TEXT,           -- 例如 "preferences"
    value JSONB,        -- {"theme": "dark", "lang": "zh"}
    created_at TIMESTAMP
);
```

**存储内容**：灵活的键值对，例如：
- 用户偏好（主题、语言）
- 个人信息（生日、邮箱）
- 阅读进度
- 任何需要跨对话共享的数据

**隔离级别**：`namespace` 级别
- 可以多级命名空间：`(user_id,)` 或 `(user_id, "preferences")`
- 支持全局或用户级别存储

## 四、前后端交互流程

### 1. thread_id 生成和传递

**前端（Vue）**：
```javascript
// 首次访问
ensureThreadId() {
  if (URL 有 thread_id) {
    threadId.value = URL 中的 thread_id;
  } else {
    threadId.value = crypto.randomUUID();  // 前端生成
    router.replace({ query: { thread_id } });  // 更新 URL
  }
}

// 发送消息
send() {
  payload = {
    message: text,
    thread_id: threadId.value,  // 传递给后端
    user_id: userId.value
  };
  await streamChat("/stream", payload);
}

// 开始新对话
startNewConversation() {
  threadId.value = crypto.randomUUID();  // 生成新的
  router.replace({ query: { thread_id } });
}
```

**后端（FastAPI）**：
```python
async def _handle_input(...):
    thread_id = user_input.thread_id or str(uuid4())  # 使用前端的

    await agent.ainvoke(
        input=...,
        config={"configurable": {"thread_id": thread_id}}
    )
```

**LangGraph 自动处理**：
- 根据 `thread_id` 从数据库读取历史 State
- 执行 Node
- 保存新的 State 到数据库（相同 `thread_id`）

---

### 2. 历史记录加载

```javascript
// 页面加载时
onMounted(async () => {
  await ensureThreadId();       // 确定 thread_id
  await loadHistory();         // 加载历史
});

async function loadHistory() {
  const res = await apiFetch("/history", {
    method: "POST",
    body: JSON.stringify({ thread_id: threadId.value })
  });
  messages.value = res.messages;  // 显示历史
}
```

## 五、使用场景

### 场景 1：多轮对话记忆（Checkpointer）

```javascript
// 用户发送第1条消息
await send("什么是AI？");
// thread_id = "abc-123"
// State 保存到数据库

// 用户发送第2条消息
await send("你刚才说的AI是指什么？");
// thread_id = "abc-123" (相同)
// LangGraph 自动加载之前的 State
// AI 可以回答："刚才提到的 AI 是人工智能..."
```

**特点**：
- ✅ 完全自动，无需手动操作
- ✅ 对话历史自动保存
- ✅ 支持多轮上下文

---

### 场景 2：长期用户记忆（Store）

```python
# interrupt_agent.py 示例
async def determine_birthdate(state, config, store):
    user_id = config["configurable"]["user_id"]

    # 1. 尝试从 store 读取
    result = await store.aget((user_id,), "birthdate")
    if result and result.value:
        birthdate = result.value["birthdate"]
        # 跨对话记得用户的生日
        return {"birthdate": birthdate, "messages": []}

    # 2. 没有，从对话提取
    birthdate = extract_from_messages(state["messages"])

    # 3. 保存到 store（跨对话持久化）
    await store.aput((user_id,), "birthdate", {"birthdate": birthdate})
```

**特点**：
- ✅ 跨对话持久化
- ✅ 需要手动读写
- ✅ 灵活的键值对存储

## 七、工作流程

```
┌──────────────────────────────────────────────────────────────────┐
│              记忆系统完整工作流程                        │
└──────────────────────────────────────────────────────────────────┘

用户操作
   │
   ▼
前端：生成 thread_id（或从 URL 读取）
   │
   ▼
前端：发送消息 + thread_id + user_id
   │
   ▼
后端：_handle_input()
   │
   ├─> thread_id = user_input.thread_id
   │
   ├─> config = {"configurable": {"thread_id": thread_id}}
   │
   ▼
后端：agent.ainvoke(input, config)
   │
   ▼
LangGraph：
   │
   ├─> 检查 agent.checkpointer 是否存在
   │
   ├─> 根据 thread_id 从数据库读取 State（如果有）
   │      ├─ messages: [历史消息]
   │      └─ 其他状态字段
   │
   ├─> 执行 Node（传入完整 State）
   │
   └─> 执行完成后，自动保存新 State 到数据库
          │
          ▼
          数据库：
          ├─ Checkpointer (thread_id 级别)
          │   └─ 保存完整 State（包括 messages）
          │
          └─ Store (手动调用)
              └─ 保存键值对（用户级）
```

## 八、总结

### Checkpointer vs Store 对比

| 特性 | Checkpointer | Store |
|------|-------------|-------|
| **自动化** | ✅ 完全自动 | ❌ 需要手动调用 |
| **设置位置** | lifespan 一次性设置 | Node 函数中添加 `store` 参数 |
| **作用域** | `thread_id`（对话级） | `namespace`（用户级） |
| **数据结构** | 完整 State（MessagesState + 自定义字段） | 键值对（JSONB） |
| **典型用途** | 对话历史、上下文记忆 | 用户偏好、个人信息、跨对话知识 |
| **API** | 无需手动调用 | `store.aget()`, `store.aput()` |

---

### 设计优势

1. **灵活配置**：支持多种数据库，通过环境变量切换
2. **自动化管理**：Checkpointer 无需手动操作
3. **连接池优化**：PostgreSQL 使用连接池提高性能
4. **隔离清晰**：thread_id 级别的对话记忆 + 用户级的长期记忆
5. **前后端解耦**：前端负责生成和管理 thread_id，后端负责持久化
