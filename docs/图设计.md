# Knowledge Base Agent 图设计

## 整体架构

Agent 采用状态图（StateGraph）模式，包含三个主要分支：

1. **Doc RAG 分支**：基于文档的检索增强生成
2. **Text2SQL 分支**：将自然语言转换为 SQL
3. **SQL Executor 分支**：SQL 校验、执行、修复和格式化

## 分支详解

### 1. Doc RAG 分支

| 节点 | 职责 |
|------|------|
| `retrieve_documents` | 从向量数据库检索相关文档 |
| `prepare_augmented_prompt` | 构建增强提示词（检索到的文档 + 用户问题） |
| `doc_model` | 调用 LLM 生成最终回答 |

**流程**：线性流程，无回环，直接输出结果。

---

### 2. Text2SQL 分支

| 节点 | 职责 |
|------|------|
| `resolve_target_db` | 解析目标数据库 |
| `retrieve_sql_schema` | 获取数据库表结构信息 |
| `retrieve_sql_examples` | 获取 SQL 示例 |
| `prepare_sql_context` | 整合 schema 和 examples，构建 SQL 生成上下文 |
| `text2sql_model` | 调用 LLM 生成 SQL 语句 |

**流程**：线性流程，生成 `generated_sql` 后进入 SQL Executor 分支。

---

### 3. SQL Executor 分支

这是最复杂的分支，包含状态机驱动的修复机制。

#### 核心节点

| 节点 | 职责 | 设置的状态字段 |
|------|------|----------------|
| `validate_sql` | 校验 SQL（权限、语法、LIMIT） | `sql_flow_state`、`sql_validation_error` |
| `execute_sql` | 执行 SQL 并处理结果脱敏 | `sql_flow_state`、`sql_exec_error` |
| `repair_sql` | 使用 LLM 修复错误的 SQL | `sql_flow_state=INIT`、`sql_attempt++` |
| `format_sql_result` | 格式化最终结果（错误或成功） | - |
| `sql_transition` | **统一决策节点** | `next_node`、`termination_reason` |

---

## 状态机设计

### SqlFlowState 枚举

```python
class SqlFlowState(str, Enum):
    INIT = "init"                      # 初始状态 / repair 后准备重新校验
    VALID_OK = "valid_ok"              # 校验通过
    VALID_NOT_SELECT = "valid_not_select"  # 非SELECT或不允许的操作
    VALID_ERROR = "valid_error"        # 校验失败（语法、LIMIT等，可修复）
    EXEC_OK = "exec_ok"                # 执行成功
    EXEC_ERROR = "exec_error"          # 执行失败（运行时错误，可修复）
```

### 状态转换规则

| 当前状态 | 条件 | 下一节点 | termination_reason |
|----------|------|----------|-------------------|
| `INIT` | - | - | （repair 后自动转 validate） |
| `VALID_OK` | - | `execute_sql` | - |
| `VALID_NOT_SELECT` | - | `format_sql_result` | `not_select` |
| `VALID_ERROR` | `attempt < 5` | `repair_sql` | - |
| `VALID_ERROR` | `attempt >= 5` | `format_sql_result` | `validate_max` |
| `EXEC_OK` | - | `format_sql_result` | `exec_ok` |
| `EXEC_ERROR` | `attempt < 5` | `repair_sql` | - |
| `EXEC_ERROR` | `attempt >= 5` | `format_sql_result` | `exec_max` |

## 核心设计原则

### 1. 单一决策点

所有路由决策收敛到 `sql_transition` 节点，其他节点**只负责业务逻辑和状态设置**，不做路由决策。

### 2. 职责分离

| 节点 | 做 | 不做 |
|------|-----|------|
| `validate_sql` | 校验 SQL、设置 `sql_flow_state` | 决定下一步、修改 `sql_attempt` |
| `execute_sql` | 执行 SQL、设置 `sql_flow_state` | 决定下一步 |
| `repair_sql` | 生成新 SQL、递增 `attempt`、清理错误字段 | 决定下一步 |
| `format_sql_result` | 格式化输出 | 决定是否继续 repair |
| `sql_transition` | 决定下一节点、写 `termination_reason` | 业务逻辑 |

### 3. 状态驱动

- **状态字段**：`sql_flow_state` 是唯一的状态驱动字段
- **决策字段**：`next_node` 是由 `sql_transition` 写入的临时字段，用于图的 conditional edge
- **追踪字段**：`termination_reason` 只在 `sql_transition` 中写入，确保终止原因的唯一性和可追溯性

## 图路由逻辑

### Conditional Edges

1. **route_query → {doc, text2sql}**
   ```python
   lambda s: s.get("route", "doc")
   ```

2. **sql_transition → {execute_sql, repair_sql, format_sql_result}**
   ```python
   lambda s: s.get("next_node", "format_sql_result")
   ```

### Edges

- **Doc 分支**：线性流程
- **Text2SQL 分支**：线性流程
- **SQL Executor 分支**：
  - `text2sql_model → validate_sql`
  - `validate_sql → sql_transition`
  - `execute_sql → sql_transition`
  - `repair_sql → validate_sql`（回环）
  - `format_sql_result → END`

---

## 错误处理与重试机制

### 最大重试次数

```python
MAX_ATTEMPTS = 5
```

### 重试场景

1. **校验错误**（`VALID_ERROR`）：
   - 尝试修复，最多 5 次
   - 超过限制则终止

2. **执行错误**（`EXEC_ERROR`）：
   - 尝试修复，最多 5 次
   - 超过限制则终止

### 不可修复场景

1. **非 SELECT 操作**（`VALID_NOT_SELECT`）：
   - 直接终止，不尝试修复

## State 字段映射

| 字段 | 来源 | 用途 |
|------|------|------|
| `route` | `route_query` | 主路由决策 |
| `generated_sql` | `text2sql_model` / `repair_sql` | 生成的 SQL（可能被修复覆盖） |
| `validated_sql` | `validate_sql` / `execute_sql` | 校验后的规范化 SQL |
| `sql_validation_error` | `validate_sql` | 校验错误信息 |
| `sql_exec_error` | `execute_sql` | 执行错误信息 |
| `sql_attempt` | `repair_sql` 递增 | 重试次数计数 |
| `sql_flow_state` | `validate_sql` / `execute_sql` / `repair_sql` | 流程状态 |
| `next_node` | `sql_transition` | 下一节点标识 |
| `termination_reason` | `sql_transition` | 终止原因 |
| `sql_error_stage` | `validate_sql` / `execute_sql` | 错误阶段（validate/execute） |
| `sql_error_type` | `validate_sql` / `execute_sql` | 错误类型（not_select/parse_error/runtime_error） |

## 设计优势

1. **简化条件判断**：从 2 套条件函数（`should_repair_after_*`）合并为 1 个统一决策节点
2. **清晰状态流转**：通过 `SqlFlowState` 枚举显式表达状态机
3. **单一职责**：每个节点职责边界清晰
4. **易于维护**：新增状态或修改路由逻辑只需修改 `sql_transition`
5. **可追溯性**：`termination_reason` 唯一来源，便于调试和分析
